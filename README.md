# カロリー帳（ダイエット記録アプリ）

**公開中 → https://choppermoon1623-tech.github.io/diet-log/**

食事と消費カロリーの記録に特化した、iPhone 向けの単一 HTML アプリ。
`index.html` 1ファイルだけで動く。外部ライブラリなし・通信なし。

- 原本：`Desktop\ClaudeCode\diet-log`
- デプロイ元：`devpps\diet-log`（`main` に push すると GitHub Pages が更新される）

## できること

| タブ | 中身 |
|---|---|
| 📝 きょう | 日付を送りながら、朝昼夕＋間食の食事と運動を記録。収支（摂取−消費）が大きく出る |
| 📈 きろく | 直近7日の平均収支、収支の棒グラフ（14日）、体重の折れ線（60日）、日ごとの一覧 |
| ⭐ 定番 | よく食べる物・よくする運動を登録。「きょう」から1タップで入る |
| ⚙️ 設定 | 身長・年齢・活動量・目標、応援モード、Dropbox へのバックアップ、計算の説明 |

- 食品データ **149件**（主食／めん・丼／外食／肉魚卵／野菜汁物／飲みもの／おやつ／調味料）、量は ×0.5〜×2 で調整可
- 「🔍さがす」でことばを入れると、さらに2つから探せる
  - **食品成分表（八訂）全2,478食品**…アプリに同梱（オフラインで動く）。100gあたりの値なので、グラムを入れて計算する。「鶏むね→にわとり むね」「ごはん→水稲めし」のような言いかえ表で、ふだんの言い方でも当たるようにしてある
  - **市販の商品**…[Open Food Facts](https://world.openfoodfacts.org/)（無料・登録不要）をボタンを押したときだけ検索。1食ぶん／グラムで入れられる。バーコードの数字でも引ける。だれでも登録できるデータなので誤りもあり、日本の商品は少なめ
  - 成分表は https://www.mext.go.jp/a_menu/syokuhinseibun/mext_01110.html の「第2章（データ）」Excel から `[食品名, kcal, 食品群]` だけを抜き出して `SEIBUN` に埋めこんだ
- 運動データ **35件**（METs 付き）、時間は 10〜60分から選択
- どちらも見つからなければ手入力でき、そのまま定番に登録できる

はじめから入っている定番には、自作メニューを入れてある（数字は目安なので、実物に合わせて直す前提）：

| 定番 | kcal | 見積もりの内わけ |
|---|---|---|
| プロテイン ホエイ割り | 150 | プロテイン1食分 約25g（95）＋ 自家製ヨーグルトのホエイ 200ml（50） |
| オートミール 30g | 114 | 乾燥 30g |
| 手作りギリシャヨーグルト 100g | 100 | 全乳ヨーグルトを半量まで水切りした換算 |
| 黒酢はちみつブルーベリー | 90 | 黒酢 大さじ1（9）＋ はちみつ 大さじ1（65）＋ 冷凍ブルーベリー 30g（15） |
| 冷凍ブルーベリー ひとつかみ | 15 | 約30g |

## 応援モード（キャラクター「カロン」）

「きょう」の画面の収支カードの下に、その日の様子に合わせて声をかけてくれるキャラクターが出る。
設定タブで オン/オフ と名前の変更ができる（既定は「カロン」）。

| 表情 | 出る場面 | ひとことの例 |
|---|---|---|
| `smile` | まだ記録がない | 朝昼夜で文を変えて呼びかける |
| `cheer` | マイナスだが目標未満 | 「あと250kcalで今日の目標だよ」 |
| `joy` | 目標達成／体重が減った／連続達成の節目 | 「0.6kg 減ってるよ。がんばったね！」 |
| `gentle` | 食べすぎた日 | 責めない。「1日くらい平気だよ」 |
| `worry` | **減らしすぎ** | 「基礎代謝のぶんは食べたほうが、かえってやせやすいよ」 |

**減らしすぎを、ほめないのが肝。** 摂取が基礎代謝を150kcal以上下回るか、赤字が目標＋800kcalを超えたら `worry` に落ちる。
同時に収支カードも、月4kg（週1kg）を超えるペースなら「達成 ✓」を出さず「減らしすぎ」に切り替え、
文言も「目標クリア」から「体に無理がかかります」に変える。数字とキャラが食い違わないようにしてある。

ひとことは日付から選ぶので、**同じ日のあいだは描き直しても変わらない**（記録を足して状況が変われば変わる）。

### キャラクターの絵

`chara/` に原本がある。**Codex に描かせたインラインSVG**で、画像ファイルは使わない。

- `chara/chara.js` — 5表情のSVG（これを `index.html` に貼り込んである）
- `chara/preview.html` — 5種を並べて見るページ
- `chara/prompt.md` — Codex に渡した指示

体・髪・服・顔のパスは5種で共通、差し替えるのは目・眉・口・ほお・腕だけ。だから表情を変えても同じ子に見える。
`viewBox` は5種とも `5 17 217 222` にそろえてある（`joy` のバンザイした手が `0 0 200 240` からはみ出すため、
全部を含む枠に統一した。ここがずれると表情ごとに大きさや位置が変わる）。

描き直したいときは `chara/prompt.md` を直して `codex exec --sandbox workspace-write "$(cat chara/prompt.md)"`。
できばえは `chara/preview.html` をヘッドレスChromeでPNGに焼くと確認できる。

配色は固定で、応援パネルの背景だけライト／ダークで少し変える（キャラが暗い背景に埋もれないよう、
パネルは両方のテーマで明るいままにしてある）。

## 写真からカロリーを入れる

API キーもサーバも使わず、**Claude アプリに聞いて答えを貼り戻す**流れにしてある。追加コストはゼロ。

食事の追加シート →「📷 写真」タブ：

1. **質問文をコピー**（`PHOTO_PROMPT`）。器の大きさから量を推定させ、調理油やドレッシングも足させ、幅ではなく代表値を出させ、最後に `品名|カロリー` の行だけを並べさせる指示になっている
2. **Claude を開く**（`https://claude.ai/new`）。カメラで食事を撮って、その文を貼って送る
3. **返事をまるごと貼る** → `parseMealText()` が品名とカロリーを拾う

読み取った品はチェックを外したり数字を直したりしてから、まとめてその食事に入る。`合計` の行は品目にせず、Claude の言う合計として脇に出して突き合わせに使う。

`parseMealText()` は返事の形のぶれに強くしてある。前置きの文章、`**太字**`、箇条書き（`-` `・` `1.`）、縦棒（`|` `｜`）・コロン（`:` `：`）・`…` 区切り、`約400kcal` のような書き方、区切り線、いずれも通る。地の文は落ちる（カロリー表記で終わらない行、30字を超える品名、0以下や5000超の数値は捨てる）。

なぜ API を使わないか：このアプリは静的 HTML でサーバがないので、API を使うならキーをブラウザに置くか中継を立てるかになる。個人利用ならどちらも可能だが、貼り戻し方式ならキーの管理もコストも発生しない。API 方式に切り替えたくなったら、`readAnswer()` の前段に fetch を挟むだけで済む形にしてある。

## カロリーの計算

**消費 ＝ 基礎代謝 ＋ 生活の活動 ＋ 運動**

- 基礎代謝：ミフリン・セントジョー式（体重・身長・年齢・性別）
- 生活の活動：基礎代謝 ×（活動係数 − 1）。活動係数は 1.20 / 1.30 / 1.45 / 1.60 から選ぶ
- 運動：`(METs − 1) × 1.05 × 体重kg × 時間h`
  - **1METs を引いている**のがポイント。安静時の消費はすでに基礎代謝で数えているので、引かないと二重計上になる。そのぶん他のアプリより少し小さい数字が出る

体重は日ごとに記録でき、その日の記録がなければ直近の過去の値を使う。

## データの置き場所

この端末の `localStorage`（キー `dietLog_v1`）だけ。サーバには一切送らない。

Dropbox へは **手動バックアップ**でやりとりする：

- 設定 →「📤 書き出す」→ iPhone の共有メニュー →「"ファイル"に保存」→ Dropbox
- 設定 →「📥 読みこむ」→ Dropbox の `dietlog_YYYYMMDD.json` を選ぶ
  - 読みこみ方は2通り：**まるごと置きかえ** / **記録のない日だけ足す**（機種変更や複数端末の合流用）

## iPhone での使い方

Safari で開いて、共有ボタン →「ホーム画面に追加」。
全画面のアプリのように立ち上がる（`apple-mobile-web-app-capable`）。
セーフエリア対応・ダークモード対応・タップ時のズーム抑止済み。

## この会話の外から入った改良（2026-09-22）

リポジトリに別途 `636a2e5 Improve daily log editing, summaries and storage reliability` が入っていた。
消さずに統合してある。内容：

- **アクセシビリティ** — `user-scalable=no` を撤去（拡大できるようになった）、`focus-visible` の輪郭、
  `aria-label` / `role="dialog"` / `aria-live`、タップ領域44px、`prefers-reduced-motion` 対応
- **データ検証** — `validateDB()` / `validateProfile()` が、読み込み時と取りこみ時に形と数値を検査する
- **保存の信頼性** — 保存に失敗したらメモリ上の変更を巻き戻し、赤い帯で知らせる（黙って壊れない）
- **記録の編集と取り消し** — 記録をタップして編集、削除は「元に戻す」で戻せる
- **言い方の正直さ** — 「記録した摂取 − 1日の**推定**消費」「消費カロリーは推定です」

応援モードと衝突した5か所は、どちらも生かす形で解決した（詳しくは `50cb724` のコミットメッセージ）。
とくに収支カードは、励ましの文を出しつつ「推定です」の注意書きを別行で必ず出すようにしてある。

## 作りのメモ

- 単一ファイル。`<script>` 内に食品/運動データ・状態・描画がすべて入っている
- 描画は「状態を変えて `render()` を呼ぶ」だけの素朴な作り。仮想DOMなし
- グラフは inline SVG を文字列で組み立てている（`balChart` / `weightChart`）
- 色は先頭の `:root` 変数に集約。`prefers-color-scheme: dark` で入れ替え
- 応援モードは `cheerOf()` が状況から表情とひとことを決め、`cheerHTML()` が描く。`CHARA` が未定義でも画面は壊れない作り
- 写真タブの3ステップは `.step` の縦線つきレイアウト。質問文は `PHOTO_PROMPT` 定数1本
- クリップボードは `navigator.clipboard.writeText()`。使えないとき（`file://` など）は質問文の textarea を選択状態にするフォールバックに落ちる
- `onclick="f('名前')"` に食品名を埋めているので、`jsq()` で **JS文字列 → HTML属性** の二重エスケープをかけている（`esc()` だけだと `'` を含む名前で壊れる）
- 中身が空の日は `save()` のたびに捨てる（日付を送っただけで空データがたまらないように）

## 注意

食品のカロリーは日本食品標準成分表などをもとにした**1人前のおおよその目安**。
数字そのものより、続けた日数と体重の線を見るためのもの。
